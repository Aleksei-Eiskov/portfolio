BUG REPORTS
EX. 01Forgot password link opens a 404 pageMedium priority

The login page links to a missing route. A logged-out user cannot start the password reset flow.

AuthenticationLogged-out userLogin page accessible

Steps to reproduce

  1. Navigate to the login page.
  2. Click the “Forgot password” link.
  3. Observe the page and destination URL.

Expected

The password reset page opens with an email field and submit button. Its title and heading identify the reset flow.

Actual

A 404 Not Found page appears because the link points to a missing route.

The source report references a screenshot and HAR file. Those attachments are not included in this portfolio export.

EX. 02Payment timeout clears the cart and leaves a pending orderHigh priority

After a payment-provider timeout, the UI shows an error and empties the cart while an order remains pending in the backend. The user receives no confirmation and cannot retry without adding the items again.

CheckoutGuest userIn-stock productClean session

Reproduction outline

  1. Add an in-stock product to the cart and proceed to checkout as a guest.
  2. Fill in shipping details and select a shipping method.
  3. Use a payment sandbox configured to reproduce a provider timeout.
  4. Submit the payment; inspect the cart and the backend order state.

Expected in the sample report

The cart stays intact, no order is created, and the user can retry payment.

Actual

The cart is cleared and an order exists with Pending status. The user must re-add the items to retry.

Adapted reproduction outline: the export does not include a verified timeout setup or its referenced HAR and screenshots. The expected order behavior depends on the product’s payment requirements.

TEST CASES
Login with valid credentialsHigh priority
TC-LOGIN-VALID-001Auth · Web · Chrome

Preconditions & data

A verified user exists and is logged out with a clean session. Use valid_user@example.com and its valid password. Exercise both Remember me states.

ActionExpected result
1. Open /loginHTTP 200. Email and password fields are visible; no authenticated user menu.
2. Enter valid credentialsValidation passes. Password remains masked; no inline errors.
3. Set Remember meThe selected state remains after blur or scrolling.
4. Submit loginOne POST /auth/login request. Credentials are absent from the URL; progress is indicated.
5. Inspect the responseHTTP 200 with a session cookie or token; no error notification.
6. Check the redirectThe dashboard or intended private page opens with the correct URL and heading.
7. Check authenticated UIUser menu is visible, the login link is hidden, and private content is accessible.
8. Restart the browserSample requirement: Remember me on preserves login; off requires authentication again. Check under a defined browser session-restore configuration.
Apply a promo code in the cartMedium priority
TC-PROMO-CODE-PAIRWISE-001Cart · Promotions

Vary user status, device, discount type, promo validity and minimum spend. The original sample uses an eight-row combination matrix; full pairwise coverage is not verified here.

Execution

  1. Set the user state and viewport for the row.
  2. Prepare a cart above or below the code’s minimum-spend threshold.
  3. Enter the corresponding promo code and click Apply once.
  4. Check the response, discount, rounding and recalculated totals.
  5. Remove an applied code and verify original totals return.
  6. Refresh and verify the intended cart and promo state persists.

Valid + minimum met

The correct discount applies once and totals recalculate according to the promotion rules.

Expired or below minimum

No discount is applied. A specific error explains the rejection; totals remain unchanged.

Car_store

A local demo API for cars and brands

POSTMAN · E2E COLLECTION

Choose a request to explore its checks.

Run the collection locally

1. Start the demo API

Clone the separate Car_store repository ↗, open its folder, then run:

npm install
npm start

The collection uses http://localhost:3001.

2. Import and run in Postman

Download the E2E collection below. Import it into Postman and select an environment with baseUrl set to your local API URL. Run all seven requests in their original order using Collection Runner.

The scripts save generated values and IDs in the selected environment. The final two requests delete the created car and brand.

This page explains the collection; it does not send API requests or display a recorded test run.

Additional collection: CRUD exploration

A separate set of requests for cars, brands, reviews, filters, search, sorting and pagination. These are manual exploration examples; the exported collection does not include implemented assertion scripts.

Some requests use fixed IDs. Review the data and update IDs before sending requests, especially DELETE and database reset requests.
